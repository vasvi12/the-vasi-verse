# Builds Page PRD

**Product:** The Vasi Verse
**Page:** Builds
**Version:** 1.0
**Status:** Locked

---

## Purpose

The Builds page showcases products, ventures, and consulting engagements that Vasavi has personally contributed to. Unlike a traditional portfolio that lists experience chronologically, Builds presents each project as a product.

Each build should communicate why it existed, the problem it solved, Vasavi's role, the product thinking involved, and where to explore complete documentation. The page exists to establish credibility through execution.

## User Goal

A recruiter should quickly understand: What has Vasavi actually built? How complex were these products? What role did she play? Is there documentation proving the work? The page should naturally encourage users to open detailed documentation.

## Layout

Navigation → Page Hero → Three Premium Product Cards → Footer. No timelines. No paragraphs explaining experience. The cards are the experience.

## Hero

Large Title: BUILDS. Subtitle: "Products I've built, businesses I've scaled, and product decisions I've documented." Supporting Copy: "Every build represents a different stage of my journey—from building a service business, to validating a product idea, to consulting on product strategy." Minimal. Maximum three lines.

### Hero Metadata

PROJECTS 3 · DOCUMENTATION Available · LAST UPDATED August 2026. Displayed using Geist Mono.

## Card Layout

Three vertically stacked cards. Each card occupies approximately 70–80% of the viewport width. Cards alternate visual composition to create rhythm:

- Card 1: Image Left, Content Right
- Card 2: Content Left, Image Right
- Card 3: Image Left, Content Right

This creates a premium editorial flow.

Every Build card follows the same structure: Hero Image → Status Badge → Product Name → One-Line Summary → Metadata → Highlights → Primary CTA → Secondary CTA. Consistency is mandatory.

## Images

Every card requires a unique hero visual.

- StudioAI: Dark AI dashboard, 3D product mockup, workflow visualization.
- Growth Alpha: Analytics, growth charts, brand strategy, minimal dashboard.
- DotRyder: Dark navigation map, ride-hailing interface, mobility visualization.

Never use logos. Never use stock images. Create original visuals matching the brand.

## Hover Interaction

Card → Elevation +4px → Image zoom 1.02× → Border becomes Accent Blue → CTA arrow animates → Cursor becomes OPEN →. Duration 450ms.

## Card Click

Cards themselves remain interactive. Clicking anywhere on the card opens a dedicated overview page. The CTA opens the full Notion documentation in a new tab. This provides two exploration paths: Website Overview → Deep Documentation.

## Card Metadata

Displayed in Geist Mono. Example: ROLE — Founder & Product Manager; STATUS — Validated; YEAR — 2026; TYPE — Founder Product. Labels always uppercase. Values use Inter.

## Section Rhythm

Each card separated by approximately 120px of vertical spacing. Large breathing room. Scrolling should feel cinematic. No crowded layouts.

## Responsive Behaviour

Desktop: Alternating left/right layouts. Tablet: Image above, content below. Mobile: Single-column stacked cards. Maintain identical spacing system.

## Accessibility

Cards keyboard accessible. Entire card clickable. Focus state visible. Alt text required for every visual. All CTAs descriptive.

## Performance

Images lazy-loaded. Optimized WebP format. Motion remains at 60 FPS. No layout shift.

## SEO

Each Build should have a unique URL, unique title, unique description, Open Graph image, and structured metadata.

## Acceptance Criteria

A recruiter should understand each product in under 30 seconds. The page should encourage exploration rather than overwhelm. Every card should feel like opening a premium software product. Users should clearly distinguish between founder work, consulting work, and product work.

## Future Scalability

Future builds can be added without changing the layout. Examples: HootMe, Future Startup, Open Source Product, Internal Tools. The card system should support unlimited expansion.

## Final Principle

Builds should not read like an Experience section. It should feel like a curated product lineup. Every project deserves the same level of presentation that companies give to their flagship products.
